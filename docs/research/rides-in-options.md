# Rides in: do we have the best options? An audit, October 2026

_Research of 2026-10-09 and 10 for the question Martin asked: do riders have the best possible ways to get their rides into Kadence easily, by upload or by sync, from the devices and apps they actually use? Run as one orchestrated workflow of 67 agents: six lenses in parallel (Garmin, the other makers and the relays, the phone and the browser, the indoor apps, Kadence's own code, what peers do), every claim handed to two independent verifiers prompted to refute it, three judges ranking the routes per persona, one synthesis, a critic naming what the synthesis missed, and a second round on four of the gaps with the same refute passes. The text below is the synthesis's second revision as the workflow returned it, read once more by hand before it was filed; the labels are the verifiers', not a person's. The September note (`garmin-without-partner-access.md`) is the baseline and is not repeated here; `workouts-to-devices.md` covers the other direction. Nothing was tried on a device; the device-in-hand week (§4, item 2) is where that happens. Private e-mail is paraphrased. What follows from it sits in the backlog (A-07, P2-01)._

**Short answer.** For the ways in that need no key from anyone and no password, Kadence already has the best set a web app can have, and no benchmarked peer documents more. What it does not have is anything automatic, for the file or for the figures, and nothing of it has met a real Edge, a real phone or a real trainer. The majority rider, an Edge and an iPhone, has an eight-tap detour through Garmin's website that the app never explains. The one automatic route open to minors in the EU without a partner key is Tredict, in two variants with four written answers outstanding, and it also carries a Zwift or Rouvy winter but not MyWhoosh or TrainingPeaks Virtual. The cheapest automatic step is not a file at all: every weekly view a coach or parent uses reads only a ride's figures, and a summary intake would let those arrive free while the file comes later, paid or by cable. The order of what to build turns on one thing nobody has asked yet: what the winter's riders carry and where they ride indoors.

_Written 2026-10-10. ## 1. Verdict

### 1.0 What changed since the first synthesis, and why

1. **"Nothing automatic exists" is split in two.** The code [verified] says every weekly and seasonal view a coach or parent uses (calendar match and colour, load/fitness/fatigue/form, the DCU corridor and season page, all twelve guardrail kinds, the attention list, the parents' week, the rider's load curve) reads only `onDate`, `sport`, `movingSeconds`, `distanceM`, `load`, `rpe` and `startedAt` (plus `title`, `feel`, `source` cosmetically; "who rode along" also uses the first GPS fix when both rides have one and degrades to time gap plus distance ratio without it). The file feeds only the ride page's map, streams, step-by-step verdict, laps, climbs, time in zones, power curve and records, HR drift, kJ, and the `power` load method (`byPower` takes a 1 Hz stream or a weighted power; average power alone falls through to HR, then RPE). But the code also says [verified] no summary intake exists: `importFitIn` requires bytes and always writes `activity_files`, the only other insert is the manual `complete.ts`, and `activities_source` allows exactly `fit, wahoo, garmin, polar, manual`. So the verdict now reads: nothing automatic exists in the repository for the file or for the figures; the cheapest automatic route is a summary route plus a summary intake (M: service, source value migration, upgrade-in-place when the file arrives later, a third ride-page state, an ADR 0016 decision on average power). Summary routes re-enter the ranking (Tredict's free list first, Connect IQ summary second, a Health Connect forwarder third) instead of being refuted as "never the file". Martin's one-line product answer ("for a rider whose figures arrive by themselves and whose file arrives later or never, what does the coach lose this winter?") could not be obtained in a non-interactive run; the code's answer stands beside it.
2. **Tredict is two routes, not one.** Tredict's OAuth docs [verified] give the same endpoints for both (`GET /api/oauth/v2/activityList`, `GET /api/oauth/v2/activity/file/{id}`), no webhooks (so both poll), an access token "valid for two days", a refresh token that "never expires" (rotated on every refresh under PKCE; 403 on refresh after deregistration), `402` only on writes, and the two-week deactivation only on the Personal API page. The first synthesis's "token sleeps after 14 days" is therefore the rider's-own-token variant's property; whether an OAuth refresh token is exempt is **[unverified]** (not asked; Martin's 2026-10-09 mail asked only the extendedSummary question). Whether the file needs paid full access under OAuth is **[unverified]** (the written yes of 2026-09-30 answered a Personal-API-framed question; the OAuth-framed one of 2026-09-29 went unanswered). Whether Tredict issues a client to an AGPL project and per self-hosted installation is **[unverified]** (asked 2026-09-29, dropped); the precedent is GoldenCheetah, which ships a public PKCE client id in its source, contributed by Tredict's own operator (PR 4870, merged 2026-05-12). Tredict's own written advice: the riders' own tokens first, an OAuth connection "if the winter's test succeeds". A reply draft with the three OAuth questions sits unsent in Martin's Gmail (created 2026-10-10). Two code facts for the adapter [verified]: Tredict's token answer carries `expires_at` as a lifetime in seconds, and `src/modules/devices/oauth.ts` accepts only `expires_in`; the OAuth variant fits `DeviceProvider` minus the webhook half, the token variant does not fit it at all.
3. **The indoor premise holds for Garmin, not for Tredict.** Garmin forwards nothing uploaded by a third party [verified in the first round: Terra; corroborated by the critic's Runalyze and Garmin-forum sources, not re-fetched], so a Garmin relay carries no Zwift, MyWhoosh or Rouvy ride. But Tredict pulls Zwift (official API, changelog 2026-07-14) and Rouvy (2026-10-07) directly, and lists Hammerhead Karoo, Wahoo, COROS, Suunto, Polar Flow and Dropbox as sources [verified]. So a Tredict adapter carries a Zwift or Rouvy winter; it does not carry MyWhoosh (no Tredict, no Garmin Connect connection, no public API; a per-ride FIT on the website; a local folder on Mac and Windows documented only by third-party tools) or TrainingPeaks Virtual (a local `FitFiles` folder on Windows, Mac, Android and the iOS Files app; Garmin and Strava connections only). Whether Zwift- or Rouvy-sourced rides appear in Tredict's `activityList` and whether their file is the original and paid is **[unverified]** (Tredict's docs name no source field). The build order therefore turns on the inventory: a Zwift/Rouvy team makes Tredict first; a MyWhoosh/TPV/Apple TV team makes the family-computer folder helper or the Strava batch first. Rulle (ADR 0033) is already a zero-upload path for planned indoor sessions.
4. **Bluetooth from the Edge into Chrome, assessed for the first time.** Chrome [verified]: Garmin's UUIDs are not blocklisted, Android requests MTU 517, writes cap at 512 bytes, notifications work, on-demand pairing is implemented on Android and Mac only, Windows confirm ceremonies sit behind a flag off by default, Safari has no plan. Gadgetbridge 0.95.0 [verified]: GFDI over GATT in about 2,600 lines of core plus about 1,200 of handlers a port would have to read; fetch confirmed only for Edge 1040, 130 Plus and Explore 2; 540/840/1050 "partially supported" with no feature list; the 520 Plus serves files only over Classic RFCOMM, which a browser cannot open; 530/830 are `isExperimental()` with no sync success in fourteen months of an open issue; the Edge pairs with one phone at a time (540/840/1040/1050 manuals; Garmin staff for the 530); once accepted as "the phone" the Edge pushes OAuth-bearing HTTP requests that a client must refuse and never fake (fake answers invalidate the device's credentials). Position: no-go as a product route this winter; go for one afternoon with an Edge 840 and 1040 in Chrome on an Android phone and a Mac; a port is L.
5. **Two critic gaps stay open.** The Strava archive as a repeatable weekly batch (allowed frequency, zip size, Safari on iPhone) and which computer a rider has (Windows, Mac, Chromebook, none; whether ChromeOS exposes an MTP Edge to the folder picker) were not researched. Both are carried as inventory questions and device-week items.

### 1.1 Where the three judges and the second round agree

1. For keyless, password-free ways in, Kadence already has the best set a PWA can have: browser upload of FIT/TCX/GPX bare, gzipped or zipped (ADR 0019/0022); "Hent fra enheden", the cabled bike computer picked as a folder with only unknown rides sent (ADR 0029); the installed app as an Android share target; an upload key per rider with `scripts/send-rides.sh` (ADR 0029); the Strava archive read in the browser (ADR 0030); Rulle recording a planned trainer session itself (ADR 0033). **[verified]** TrainingPeaks' documented fallback when Garmin Connect is down is Kadence's cable route word for word, and no benchmarked peer documents a share-sheet import or an upload-only token.
2. None of it is easy every ride for the majority persona. A 16-year-old with an Edge 840 and an iPhone has a website detour of about eight taps or a Windows computer, and the app's copy names none of it; the only file recipe in help is Strava's. **[verified against the repo]**
3. Nothing automatic exists on any installation, for the file or for the figures (§1.0.1). The three adapters (Wahoo, Garmin, Polar) are inert for lack of keys; the only planned automatic path, Tredict, is unbuilt and waits on A-07 ("Ikke startet", while P2-01's own text says "Martin har sagt ja"; the backlog contradicts itself).
4. Tredict is the only automatic route open to Kadence that admits 14-year-olds, stays in the EU and needs no partner key **[verified]**: terms effective 2026-09-25 (14+, parental approval for minors, a reserved right to restrict read access on external interfaces without a paid period), Hamburg operator, Hetzner DE and netcup AT, USD/EUR 49 per 12 months after 2 free months (DKK 399 in the price page's country selector, read 2026-09-29), coach-assigned 3-month units. It comes in two variants (§1.0.2), it is a hub (Garmin, Zwift, Rouvy, Karoo, Wahoo, COROS, Suunto, Polar, Dropbox), and for Garmin-sourced rides Garmin's own 16+ account rule outside the US means a first-year U17's link sits on a parent's Garmin account; for Zwift-sourced rides Zwift's terms apply instead (under 18 with a parent's permission, under 16 a consent mechanism; terms 2026-06-02).
5. Everything else is closed, refuted, excluded by terms for minors, or niche: Garmin's programme (paused, business-only, key unshareable), aggregators (USD 399–499 a month per installation), Dropbox (16+ now, 18+ from 2027-01-01, US storage), Nolio (API terms forbid the personal-key pattern outright), intervals.icu and FitnessSyncer (18+), Wahoo's cloud (ToS 18+), HealthKit (an Edge-only Garmin account does not appear in Apple Health), Gadgetbridge (Android only, replaces Garmin Connect, the riders' Edges untested), the unofficial Garmin login (never). Health Connect forwarders move from "refuted" to "a documented recipe only after a summary intake exists, never shipped" (§5).
6. The next moves: ask the winter's riders what they carry and where they ride indoors; a device-in-hand week before any code; honest in-app recipes; a first-sync day budget; send Tredict the three OAuth questions with the pending one; a Windows/Mac folder helper; then the summary intake and the Tredict adapter in the variant Tredict grants; the Wahoo application with the age question first. Do not build Dropbox, Nolio, an inbox, a Gadgetbridge façade, a Bluetooth port or Connect IQ for rides in this winter.

### 1.2 Where they disagree, and the position taken here

- _Figures first or file first._ The critic: the summary routes were refuted on a premise nobody checked. Position: the code settles what the views need (§1.0.1); Martin settles whether a coach of 15–18-year-olds needs step verdicts and curves weekly or occasionally. Until he answers, P2-01's clause "ture uden fil kun hvis Felix har bekræftet det" stays as written, and the A-07 page presents "figures free and automatic, the file paid or by cable" as the choice instead of "file or nothing".
- _Size of the Tredict wave._ Judge 1 said M, Judges 2 and 3 and the backlog L. Position now: the adapter is M for the code in either variant (the ten-minute in-process timer in `src/modules/push/timer.ts` and `importFitIn` exist; the OAuth variant reuses `connect.ts`, PKCE and `links.ts`); the summary intake is a separate M; the whole wave is L once the ADR, the SECURITY DEFINER for due links on the RLS allow-list with tests, the `docs/subprocessors.md` row and the words for parents are counted.
- _Which Tredict variant._ Tredict's operator asked for the riders' own tokens first; the OAuth variant is sleep-free on paper but ungranted and its file gate unverified. Position: build the link kind so both fit (`status: sleeping` for the token variant, a `tredict` provider for OAuth), start with whichever Tredict grants in writing, and try OAuth on one rider on the hosted instance if a client is issued this winter.
- _Bluetooth from the Edge._ The critic: the only cable-less, cloud-less, app-less, MTP-proof candidate for Android and Mac. The second round: feasible on paper for the 2020+ Edges, blocked in practice by the one-phone rule, the OAuth traffic, the chooser pick per visit and the untested 540/840. Position: measure for one afternoon, do not build this winter; if the 1040 or 840 hands over files to Chrome on Android without displacing Garmin Connect, reopen as an L item for next winter.
- _Gadgetbridge._ All three judges rank it below the cable; the Bluetooth lens adds that the same Edge issues (530/830 untested, one phone, OAuth traffic) sit under it. Position unchanged: a generic bearer-token target upstream later, no façade, no recipe until a 530/830 has been seen fetching.
- _Inbound e-mail door._ Deferred by all three judges; the indoor lens adds that Zwift's in-app export on iOS and Android is e-mail-only, which would make a mail door the only in-app phone route for Zwift. Position: still defer; the zwift.com/feed download is 4–5 taps either way and the mail door would be Kadence's first mail subprocessor and scheduler.
- _Connect IQ for rides in._ Judge 1 wanted a ride-id stamp on the sessions-out app's list; Judges 2 and 3 pushed Connect IQ past the winter. Position now: Connect IQ is a summary route (a data field may call `makeWebRequest`; `Activity.Info` carries timer time, distance, averages, ascent, start, no normalized power, so a weighted power only if the field computes one), re-entering as a figures-only item behind the summary intake and the sessions-out app, not before the 31.61 crash is fixed; the ride-id stamp stays on that app's list.
- _Garmin "closed since 2026-03-25"_: reword to "new access requests paused, no public statement, no date, business use only". _Wahoo_: the ToS say 18; ask first whether 15–17-year-olds may hold an account. _First-sync caps_: S and before any adapter. _iOS Shortcuts_: a device-week experiment. _intervals.icu for U23_: open, one e-mail. Positions unchanged.

## 3. What is new since the September research (docs/research/garmin-without-partner-access.md, 2026-09-29)

### 3.1 From the second round (2026-10-10)

**The figures carry the week [verified against the code].** `insight/gather.ts` selects `id, riderId, onDate, sport, movingSeconds, distanceM, load`; `season/volumes.ts` and `season/ridden.ts` select `onDate, sport, movingSeconds`; the calendar's matched activity reaches the browser as `id, movingSeconds, load`; `compliance.ts` reads minutes and load; `guardrails.ts` has 7 training plus 5 wellbeing kinds over hours, km, dates and check-in fields; `mid_zone` counts planned structures, never activities; the parents' week reuses the same reads. `together.ts` needs `startedAt` (NOT NULL; the manual path stamps noon, so two hand-entered rides of similar distance on one day always count as ridden together) and uses the first GPS fix only when both rides have one. `activity-load.ts`: `byPower` needs `power1hz` or `weightedPower` (the FIT path computes it from the stream; the session's own `normalized_power` is never read, so the `weightedPower` branch has no production caller today), `byHr` needs `avgHr` and a threshold (floor 0.4, cap 1.05), `byRpe` needs `rpe`. File-only columns: `hrDrift, zoneSeconds, bestPowers, streams, laps, climbs, maxSpeed, workKj`; records run only when `avgPower > 0`; plan-versus-ride only when streams exist; `ride-details.tsx` treats `source !== "manual"` as file-backed. ## 5. What was refuted

### 5.1 Refuted or narrowed by the second round

- **"Nothing automatic exists" as the reason every summary route is refuted [refuted on its framing].** The weekly views, the corridor, the twelve guardrails, the attention list and the parents' week need only the figures (§3.1); the file feeds the ride page's extras and the power load method. What holds: no summary intake exists in the repository, so nothing automatic exists today for the figures either.
- **"The Tredict token sleeps after 14 days" as a property of the Tredict route [with caveats].** It is documented for personal tokens only; the OAuth docs document two-day access tokens and never-expiring refresh tokens with no inactivity clause; whether OAuth refresh tokens are exempt is unconfirmed in writing and unasked.
- **"The file needs full access" under both variants [with caveats].** Confirmed in writing for the rider's own token; the docs list 402 only on writes; under OAuth unverified.
- **"A Garmin relay carries no indoor rides, so Tredict buys little for a largely indoor winter" (the critic's premise) [refuted for Zwift and Rouvy, holds for MyWhoosh and TPV].** Tredict pulls Zwift and Rouvy directly through official APIs; Garmin's non-forwarding is irrelevant to those rides. Whether their file is the original and paid is unverified.
- **"Zwift sends completed rides only to the eight on its receive list" [refuted].** The eight are the legacy Connections; Training-API partners (Tredict among them) get completed rides back (Zwift staff; Tredict changelog).
- **"MyWhoosh documents no connected platforms and keeps no local file" [with caveats].** The help centre names none, but the App Store notes name Intervals.icu and Xert; the vendor documents no local folder, but two third-party tools read one on Mac and Windows.
- **"Summary sources never yield the power load method" [with caveats].** True for Tredict's extended summary, Connect IQ `Activity.Info` and Health Connect aggregates; Wahoo's summary carries a normalized power, and a Health Connect `PowerRecord` series could feed the stream branch.
- **F1's column list [with caveats].** `startedAt` is required ("who rode along", ordering, cursors), `title`/`feel`/`source` are read cosmetically, and companions use the first GPS fix when both rides have one.
- **"Bluetooth from the Edge: two clean-room desktop implementations exist" [with caveats].** One pulls files (gfdi, watches, Windows/Linux); the other is telemetry only; neither targets an Edge.
- **"A Gadgetbridge user reused Garmin Connect's bond and it worked" [with caveats].** The connection and notifications worked; activity sync never did; the issue is open.
- **"Garmin devices hold one BLE connection at a time" [unverified for Edges].** The source is a watch tool's README; Garmin's Forerunner 255 manual allows several phones; the documented Edge limit is one paired Garmin Connect phone, a pairing rule, not a documented link-count limit.
- **"The 2020+ Edges hand over FIT files over GATT" [with caveats].** Confirmed by Gadgetbridge for Edge 1040, 130 Plus and Explore 2 only; 540/840/1050 "partially supported" with no feature list.
- **"FileTransferHandler plus GarminSupport is about 3,000 lines" [corrected].** 2,603 at tag 0.95.0, plus about 1,200 in FileType, ChecksumCalculator, GarminByteBufferReader and ProtocolBufferHandler a port must read.
- **"The 14-day Tredict token sleep exists nowhere in Tredict's public docs" (first round's B1 fit judge) [refuted].** It is on the Personal API FAQ page.
- **"The OAuth inactivity question is in the sent reply" [refuted].** Martin's 2026-10-09 mail asked only the extendedSummary question; the three OAuth questions sit in an unsent draft.
- **"Connect IQ data-field networking only from API 5.0.0" [with caveats].** The Communications page lists Data Field among the app types and `makeWebRequest` since API 1.3.0; whether a field's request fires reliably at ride end on a 530 and an 840 needs ten rides on each.

### 5.2 Refuted in the first round, kept

- **B1, "the Tredict poller follows an established pattern among peers" [refuted on its framing].** Athletica imports completed rides from Strava only; JOIN's TrainingPeaks link is outbound. Tredict rests on its own documentation recommending BYOK for coaching apps and on the absence of any lawful alternative for minors.
- **"Garmin's programme closed to new applicants since 2026-03-25" [with caveats].** Paused by e-mail, no public closure notice, no date, business-only.
- **Dropbox as a Wahoo route [refuted as a fit].** 16+ outside the US, 18+ from 2027-01-01, US storage, Full Dropbox scope, guardian-connects design change.
- **Nolio as a relay [refuted].** API Terms v1.0 forbid the personal-key pattern even with consent; a multi-user app needs discretionary approval and a paid plan per installation; 30-day deletion on disconnect.
- **Apple Health exporters for Edge riders [refuted].** Connect does not appear in Apple Health for an Edge-only account; where it does, HR high/low only, never a file.
- **Health Connect forwarders for the file [refuted for the file; reopened for the figures].** Garmin writes HR, speed, cadence, distance, calories, no route, no power, no file; a PWA cannot read Health Connect; a forwarder app could post a session summary (type, start, end, duration, distance, cadence, HR samples) to a JSON route behind the upload key once a summary intake exists; whether Garmin writes an exercise session for an Edge-only account is unverified.
- **"Hent fra enheden" on Windows for MTP Edges [unverified].** No evidence Chrome's folder picker can enter an MTP device; help may promise Explorer copy and nothing more for the 540/840/1040/1050 until tested.
- **Wahoo "not intended under 16" [with caveats].** The Terms of Service say 18; the heart-rate anecdote has a Strava confounder.
- **FitnessSyncer, aggregators, intervals.icu for minors, the unofficial login, a Garmin browser extension, the Strava API [refuted or excluded by terms].** 18+ and US; USD 399–499 a month; 18+ by written policy; the rider's password against Garmin's terms; scraping clause; ADR 0027.
- **"The only automatic Wahoo route without API approval is e-mail" [with caveats].** Dropbox auto-share is the other; e-mail's address and attachment behaviour are unverified.
